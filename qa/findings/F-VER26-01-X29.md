## Kort
Den side-dækkende `Content-Security-Policy: frame-ancestors 'self'` fra #206 (F-AUD26-01) overskrev den strengere CSP,
som `/privat/tp-verify` selv sætter (#205: `sandbox allow-scripts; frame-ancestors 'self'`). Dermed var dokumentet
med Travelpayouts-scriptet ikke længere sandboxet på header-niveau, og main var rød i
`e2e/third-party.spec.ts:184`.

## Trin til at genskabe
1. Fake-build som CI's privat-job (`NEXT_PUBLIC_PRIVAT_FAKE=1 NEXT_PUBLIC_FUNNEL_FAKE=1 npm run build`), start med
   `NEXT_PUBLIC_TRAVELPAYOUTS_VERIFY=1`.
2. `curl -D - -H "Sec-Fetch-Dest: iframe" -H "Sec-Fetch-Site: same-origin" /privat/tp-verify`, eller
   `TP_VERIFY_BASE_URL=… npx playwright test e2e/third-party.spec.ts --project=desktop-1440`.

## Forventet
`content-security-policy: sandbox allow-scripts; frame-ancestors 'self'` på /privat/tp-verify, mens alle andre sider
beholder `frame-ancestors 'self'`, X-Frame-Options, nosniff og Referrer-Policy.

## Faktisk (før rettelsen)
`Content-Security-Policy: frame-ancestors 'self'` på /privat/tp-verify. third-party.spec.ts:184: `Expected pattern:
/^sandbox allow-scripts;/  Received string: "frame-ancestors 'self'"`.

## Rettelse
web/next.config.ts: frame-ancestors-CSP'en har `source: "/((?!api/|privat/tp-verify).*)"`. De øvrige headere gælder
stadig alle sider (852bcbf).
