## Kort
Betaling (Stripe) rapporteres som `available`, (a) selv når STRIPE_WEBHOOK_SECRET mangler, så et gemt kort aldrig når Dialogbot, og (b) når nøglen er en testnøgle (`sk_test_…`) – test-mode er ingen status, og `/billing/account` har intet felt for den.

## Trin til at genskabe
1. Kun `STRIPE_SECRET_KEY=sk_test_…` sat → GET `/integrations/capabilities` → `payment.status = "available"`, note «Stripe (testtilstand): …».
2. POST `/webhooks/stripe` svarer 503 uden webhook-hemmelighed (webhooks/router.py:42), så `checkout.session.completed` (kort gemt) aldrig behandles – men konto-siden siger efter Checkout «Tak – kortet er gemt hos Stripe».
3. Med begge sat (sk_test): capability stadig `available`; GET `/workspaces/{ws}/billing/account` → nøgler `billing_email, can_manage, card, configured, country, currency, vat, vat_number` – ingen test-mode.

## Forventet
X26: «live/test-mode/adapter-only/not-implemented … UI og API viser præcis det». Registryets egen tekst ved manglende nøgle: «Kræver STRIPE_SECRET_KEY og STRIPE_WEBHOOK_SECRET på serveren» – status bør følge samme regel. Test-mode skal kunne ses (status eller felt), så konto-siden kan sige det.

## Faktisk
`status = "available" if s.stripe_secret_key` (registry.py:59); `billing.stripe.configured()` = kun secret key (stripe.py:56); `_account_out` returnerer kun `configured: bool`.
