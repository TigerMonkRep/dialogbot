## Kort
Det nye workflow `provider-sandbox` (PR #208) er rødt på main 5c75ea3 (push-kørslen, job 131517333824): 2 af 5
sandbox-tests fejler, fordi Resend-nøglen ikke må sende fra afsenderen, testen falder tilbage til.

## Trin til at genskabe
1. `gh api repos/TigerMonkRep/dialogbot/commits/5c75ea3…/check-runs`: `provider-sandbox completed failure`.
2. Jobloggen: `tests/sandbox/test_resend_sandbox.py::test_delivered` og `::test_bounced_reaches_our_bounce_path`.

## Forventet
Grønt sandbox-job på main (Stripe test mode + Resend test-indbakker), eller tydeligt sprunget over, når afsenderen
ikke er sat op.

## Faktisk
```
RuntimeError: resend 403: {"message":"This API key is not authorized to send emails from dialogbot.dk","statusCode":403}
FAILED tests/sandbox/test_resend_sandbox.py::test_delivered
FAILED tests/sandbox/test_resend_sandbox.py::test_bounced_reaches_our_bounce_path
2 failed, 3 passed in 13.21s
```
Workflowet sætter `SANDBOX_EMAIL_FROM: ${{ vars.SANDBOX_EMAIL_FROM }}`. Variablen er tom, så
`sandbox_from()` falder tilbage til `noreply@dialogbot.dk`, og det domæne er ikke godkendt for
`SANDBOX_RESEND_API_KEY`. Stripe-delen (3 tests) er grøn.

## Muligheder
A. Fürster sætter repo-variablen `SANDBOX_EMAIL_FROM` til en adresse på et domæne, der er verificeret i Resend
   for sandbox-nøglen.
B. Testen springer Resend-delen over (skip med årsag) i stedet for at fejle, når variablen mangler.

## Evidens
- GitHub job 131517333824 (main 5c75ea3, push), log hentet med `gh api …/actions/jobs/131517333824/logs`
- Workflowet kører kun på push til main, natligt og manuelt, ikke på PR'er, så PR #208 var grøn.
